OSINT Agent – Repository & Infrastructure Overview
==================================================

Purpose
-------
This repository provides an Open Source Intelligence (OSINT) agent built with a custom lightweight agent framework (no LangGraph or LangChain). It exposes a custom agent loop that can:
- Search the open web (including Tor via a separate tool),
- Deep-crawl websites and PDFs,
- Query Wikipedia and GitHub,
- Scrape Pinterest,
- Generate image metadata/description via external services,
- Update a local knowledge base (Neo4j graph database),
- Stream text tokens in real-time using Server-Sent Events (SSE),
- Generate a final investigation report.

The agent runs as a FastAPI backend server and is accessed via a self-contained HTML/CSS chat interface served at the root URL.

Top-Level Layout
----------------
- `README.md` – Quickstart, prerequisites, and how to run the FastAPI server.
- `src/` – All Python code for the OSINT agent, custom framework, and supporting modules.
  - `agent/` – Core framework code (messages, custom `@tool` decorator, and the agent loop).
  - `llms/` – Direct API clients for OpenAI, Anthropic (Claude), and Google (Gemini) SDKs.
  - `tools/` – Concrete OSINT tools (search, crawling, database connections, scrapers, report generator).
  - `static/` – The frontend files (e.g. `index.html` chat UI).
- `docs/` – Documentation, including this architecture overview and a smoke demo guide.

Key Directories and Files (under `src/`)
----------------------------------------
- `agent/`
  - `messages.py` – Plain Python dataclasses (`SystemMessage`, `HumanMessage`, `AIMessage`, `ToolMessage`, `ToolCall`) replacing langchain message objects.
  - `tool_decorator.py` – A custom `@tool` decorator that parses function signatures and docstrings to generate OpenAI-compatible tool schemas.
  - `loop.py` – A lightweight agent execution loop that calls the LLM, yields streamed tokens in a background thread using a `queue.Queue`, executes requested tools, appends responses to thread history, and continues.
- `llms/`
  - `llm_client.py` – Abstract base class (`LLMClient`) defining the standard `invoke()`, `invoke_streaming()`, `stream()`, and `describe_image()` signatures.
  - `openai_client.py` – Concrete client using the direct `openai` Python SDK.
  - `claude_client.py` – Concrete client using the direct `anthropic` Python SDK.
  - `gemini_client.py` – Concrete client using the direct `google-generativeai` Python SDK.
  - `client_factory.py` – Decides which model client to activate based on the `LLM_PROVIDER` environment variable.
- `server.py`
  - The FastAPI application exposing API endpoints:
    - `POST /api/chat` – Receives a user prompt and returns a Server-Sent Events (SSE) stream of tool executions and token chunks.
    - `GET /api/threads` – Lists all active chat thread history metadata.
    - `GET /api/threads/{thread_id}/messages` – Retrieves full message history.
    - `DELETE /api/threads/{thread_id}` – Deletes a thread from memory.
    - `GET /api/tools` – Lists all registered tools and their enabled status.
    - `POST /api/tools/{name}/toggle` – Toggles a tool's enabled state in `tool_config.json`.
    - `GET /api/kb/{thread_id}/entities` – Retrieves extracted entities from Neo4j/local files.
    - `GET /api/kb/{thread_id}/edges` – Retrieves extracted relationships/edges.
- `static/`
  - `index.html` – A dark-themed, modern HTML interface using SSE streams, featuring a conversation history panel, a side drawer for threads, collapsible tool-call details, and direct API connection controls.
- `main.py`
  - Simple entry point script to run the FastAPI server using Uvicorn.
- `tools/`
  - `all_tools.py` – Central tool registry. Exposes `get_all_tools()` filtering tools via `tool_config.json`.
  - `engine_search.py` – Scrapes search engines and aggregators (like SearXNG/Google API).
  - `web_content_tools.py` – Crawls content from general URLs and extracts PDF text.
  - `deep_search.py` – Multi-step research tool.
  - `tor_search.py` – Dark web search tool.
  - `pinterest.py` – Pinterest scraping via Selenium.
  - `knowledge_base.py` – Handles Neo4j graphing and local file mirroring (`kb_entities.txt`, `kb_edges.jsonl`). Contains the `knowledge_agent` tool which manages ontology-based entity/relation extraction.
  - `final_report.py` – Generates structured markdown summaries.

How the Agent Runs
------------------
1. **Configure Environments**: Set up `.env` (or copy from `.env.example`) with API keys and database credentials (Neo4j, etc.).
2. **Start Server**:
   ```bash
   cd src
   uv run python main.py
   ```
3. **Open UI**: Go to `http://localhost:8000` in your web browser.

Notes for Future Changes
------------------------
- When writing a new tool, use `from agent.tool_decorator import tool` instead of LangChain's decorator, and register it in `src/tools/all_tools.py`.
- Thread history is stored in-memory in `src/agent/loop.py`. If persistent conversation history across server restarts is required, update `loop.py` to save/retrieve messages from an SQLite database.
